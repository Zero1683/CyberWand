# 算法与程序结构

算法在 ESP32-C3 上执行，网页只负责配置和显示。

```text
LSM6DS3TR-C 六轴数据（104 Hz）
  → 静止校准 / 陀螺仪零偏
  → 重力估计与扣除 / 低通滤波
  → 动作开始、结束检测
  → 截取有效运动段
  → 时间重采样为 48 × 6
  → RMS 归一化 / int16 特征
  → 与个人模板进行 DTW 匹配
  → 距离与候选差值拒绝判断
  → LED + USB + 可选无线事件
```

## 采样和自动分段

IMU 为 LSM6DS3TR-C，I²C 地址 0x6A，104 Hz，量程 ±4g / ±1000°/s。启动取 208 个静止样本校准陀螺仪零偏，并检查稳定性。采样通过轮询完成，不依赖 IMU 中断，也未实现深度睡眠。

角速度传播重力方向，再扣除重力形成线性加速度特征；用独立原始加速度稳定窗口纠正重力估计，避免一次挥动后的残余估计让设备一直无法重新待命。这不是通过两次积分获得精确空间轨迹。

自动模式先要求约 300 ms 安静窗口；运动持续约 40 ms 且角速度超过 25°/s 或线性加速度超过 0.16g 时触发。静止约 220 ms 后结束，结束阈值为 12°/s 和 0.09g，冷却约 650 ms。实际边界与质量条件以 `motion_gate.h`、`main.cpp` 为准。

网页录入 `record ID`：取消现有采集 → 三秒准备 → 等待稳定与起动 → 采一份 → 保存 → review。不会在凑满模板后偷偷回到识别。旧的 `train ID` 仍保留按 SW4 手动采集入口。

## 匹配

`recognizer.h` 定义 12 类、每类 3 个模板、48 个时间点、6 个通道。原始样本重采样后，按整段 RMS 统一缩放，保留轴符号及通道相对关系；没有任意姿态旋转不变性。

DTW 使用 ±8 点的时间带，滚动两行保存累计距离，限制内存与时间。距离阈值初值为 0.65，候选差值阈值为 0.12；至少两类有样本才启用识别。距离、margin 是匹配指标，不是百分比概率。太短、太长、动作过小、削顶、采样异常或结果接近都会拒绝。

要评估准确率：每类训练三份以后，额外采集未参与训练的测试动作，记录真值、输出和 unknown，形成混淆矩阵。不能用训练集重匹配作为真实准确率。

## 文件职责与存储

| 文件 | 职责 |
|---|---|
| `main.cpp` | 硬件初始化、采样、状态机、命令与 LED |
| `recognizer.h` | 特征归一化、DTW、模板分类 |
| `motion_gate.h` | 自动开始结束、冷却与重新待命 |
| `still_window.h` | 原始传感器静止窗口 |
| `capture_clock.h` | 采集时间计算与计时边界 |
| `custom_store.h` | 自定义模板 LittleFS 存储 |
| `transport.h` | Wi-Fi/MQTT、BLE、异步事件队列 |
| `console.h` | 原生 USB 输入输出缓冲 |

旧六类模板保存在 NVS，新六类模板保存在 LittleFS；每个模板为 48×6×2=576 字节。名称和无线配置存于 NVS。写入自定义模板采用临时文件再重命名。只有确认全空白分区才首次格式化，非空且不能挂载的分区不会自动擦除。

无线任务与采样分离，队列有界；超过时效或离线的事件不补发，避免重连后执行陈旧手势。网页后端独占串口，波形与日志列表有长度上限。
